# SP0 — Model-Completeness Triage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce the authoritative gap inventory for the model-completeness epic — one production-routed probe per remaining unmodelled mechanic, classified real-gap (`it.fails`, assigned to SP-A…G) vs already-correct FP (green `it`, locked) — plus a reconciliation table that becomes every downstream sub-project's spec input.

**Architecture:** SP0 writes NO `src` fix. For each ship, pull VERBATIM skill text from `docs/ship-skills.csv`, route it through production `buildShipAbilities`, and assert the intended faithful ability shape. Real gaps are wrapped in `it.fails` (suite stays green; when a later SP models the mechanic, `it.fails` starts failing and forces conversion to a normal `it`). Confirmed FPs stay green as regression locks.

**Tech Stack:** TypeScript, Vitest. Parser: `src/utils/skillTextParser.ts`. Builder: `src/utils/abilities/buildShipAbilities.ts`. Types: `src/types/abilities.ts`. Audit: `scripts/auditSkills.ts` + `scripts/auditSkills.allowlist.ts`.

**Spec:** `docs/superpowers/specs/2026-07-05-sp0-triage-design.md`. **Handoff:** `docs/superpowers/plans/2026-07-05-sp0-triage-handoff.md`. **Roadmap:** `docs/superpowers/specs/2026-07-05-model-completeness-epic-roadmap.md`.

## Global Constraints

- **Source of truth for skill text:** `docs/ship-skills.csv` (tagged). NEVER derive probe text from `ships.ts` (untagged / differently-worded). Resolve refit-active passive via the real production `buildShipAbilities` path (pass the raw slot text on the matching `Ship` field).
- **Production routing only:** every probe drives `abilitiesFor(over, slot)` → `buildShipAbilities(ship({...}))`. Never a hand-built ability array (the dump-fidelity trap: `Ability.scaling` / `target` / slot-routing are invisible to dumps).
- **Green-suite gate:** real gaps use `it.fails`, so the FULL suite must be GREEN. No `--no-verify`. Husky pre-commit passes normally.
- **Dump-fidelity trap → STOP-AND-REPORT:** if a probe you expect to be a real gap PASSES as a plain `it` pre-change, it is an FP. Lock it green, do NOT wrap in `it.fails`, do NOT assign to an SP, record it as FP in the reconciliation table.
- **`it.fails` hazard mitigation (binding):** exactly ONE assertion per `it.fails` probe; before wrapping, run it once as a plain `it` (or with the assertion inverted) to confirm it fails for the INTENDED reason (mechanic genuinely absent from production output), not an incidental error (wrong slot, wrong `Ship` field, typo).
- **Audit stays at 0 findings, 0 stale rows.** SP0 does not add new deferrals (the allowlist already lists these ships); only touch `scripts/auditSkills.allowlist.ts` reason text if triage reclassifies an entry, and confirm `npm run audit:skills` stays clean.
- **Goldens byte-identical.** SP0 writes no `src` fix. NEVER `vitest -u`.
- **Worktree:** `sp0/triage`, worktree-isolated. Provision: `cp <main>/.env .env`, copy ALL `docs/*.csv` + the combat-system `.md`, run `npm run prepare` (husky).
- **Gates run SERIALLY** (concurrent tsc+lint+vitest with symlinked node_modules OOMs): `npx tsc --noEmit` → `npm run lint` → `npm run audit:skills` → `npm test`.
- `gh auth switch --user TheSusort` for gh ops.

## Assertion decision rule (apply to EVERY probe)

The intended faithful behaviour is described per family below. To turn it into a compiling, non-vacuous probe:

1. **Grep the verbatim text:** `grep -m1 '^<Ship>,' docs/ship-skills.csv` (note the columns: `name, active_skill_text, charge_skill_charge, first_passive_skill_text, second_passive_skill_text, third_passive_skill_text`). Pick the slot holding the clause; put its text on the matching `Ship` field (`activeSkillText` / `firstPassiveSkillText` / `secondPassiveSkillText` / `thirdPassiveSkillText`), and query that slot (`'active'` / `'passive'` / `'charged'`).
2. **Dry-run to see current output:** write the probe as a plain `it` that `console.log`s `JSON.stringify(abilities)` and asserts the intended shape. Run `-t <Ship>`. Read the actual current ability array.
3. **If it PASSES pre-change → FP.** STOP-AND-REPORT. Keep it a green `it` (drop the console.log), record FP, do not assign to an SP.
4. **If it FAILS → real gap.** Confirm it fails for the intended reason (the ability/trigger/field is genuinely absent), then choose the assertion form:
   - **Intended trigger/type/field EXISTS in `src/types/abilities.ts`** (`on-destroyed`, `on-enemy-charged-cast`, `on-own-cleanse`, `on-debuff-resisted`, `incoming-reduction`, etc.) → assert it directly: `expect(effect?.trigger).toBe('on-destroyed')` or `expect(abilities.some(a => a.type === 'incoming-reduction' && /* condition */)).toBe(true)`.
   - **Intended trigger/field does NOT exist yet** (new event/condition/field the SP will add) → assert the strongest TYPE-VALID proxy that is FALSE today and becomes TRUE post-fix — usually `expect(effect?.trigger).not.toBe('on-cast')` (the effect currently collapses to `on-cast`; the SP's new trigger makes it non-`on-cast`), or `expect(abilities.some(a => a.type === '<existing-type>')).toBe(true)` when even the ability is absent today. Do NOT write a string literal that isn't in the `AbilityTrigger`/`AbilityType` union — it will not compile.
   - Wrap the single assertion in `it.fails`, add a `// GAP: SP-<X> — <intended shape>` comment.
5. **Record** the ship's row in the reconciliation doc: slot, verbatim clause, intended behaviour, probe result (fails/green), bucket, assigned SP, note.

/**
 * Model-completeness epic — SP0 TRIAGE PROBE CORPUS.
 *
 * One probe per remaining unmodelled mechanic, routed through the REAL production path
 * (buildShipAbilities) with skill text copied VERBATIM from docs/ship-skills.csv.
 *
 * `it.fails(...)` = a real gap: the assertion fails today (so `it.fails` is GREEN), and when the
 * assigned sub-project (SP-A…G) models the mechanic the assertion starts PASSING — which makes
 * `it.fails` FAIL, forcing that SP to drop `.fails` and convert to a normal `it`. Self-enforcing
 * handoff; the suite stays green the whole epic.
 *
 * Plain green `it(...)` = a false positive (behaviour already correct) locked as a regression guard.
 *
 * Each `it.fails` carries exactly ONE assertion (the it.fails masking hazard: it goes green if ANY
 * assertion throws, including for the wrong reason) and a `// GAP: SP-<X>` comment.
 */
import { describe, it, expect } from 'vitest';
import { buildShipAbilities } from '../buildShipAbilities';
import { Ability, Skill } from '../../../types/abilities';
import { Ship } from '../../../types/ship';

function ship(over: Partial<Ship>): Ship {
    // eslint-disable-next-line @typescript-eslint/no-explicit-any
    return { ...({} as any), refits: [{}, {}, {}, {}], ...over } as Ship;
}

function slot(skills: Skill[], name: string): Skill | undefined {
    return skills.find((s) => s.slot === name);
}

export function abilitiesFor(over: Partial<Ship>, name: string): Ability[] {
    return slot(buildShipAbilities(ship(over)).slots, name)?.abilities ?? [];
}

describe('SP0 triage — corpus scaffold', () => {
    it('abilitiesFor helper is available', () => {
        expect(typeof abilitiesFor).toBe('function');
    });
});
